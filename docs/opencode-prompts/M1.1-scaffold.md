## Conteúdo de cada arquivo

### backend/requirements.txt
fastapi==0.111.0
uvicorn[standard]==0.29.0
sqlalchemy==2.0.30
aiosqlite==0.20.0
pydantic==2.7.1
pydantic-settings==2.2.1
pytest==8.2.0
pytest-asyncio==0.23.6
httpx==0.27.0

### backend/app/config.py
Classe Settings usando pydantic-settings com:
- DATABASE_URL: str = "sqlite+aiosqlite:///./data/swimtimer.db"
- RESET_PASSWORD: str = "maratona2025"
- HOST: str = "0.0.0.0"
- PORT: int = 8080

### backend/app/database.py
- AsyncEngine com create_async_engine
- AsyncSessionLocal com async_sessionmaker
- Base declarativa
- Função get_db como dependency do FastAPI
- Função init_db que cria as tabelas

### backend/app/models.py
Modelos SQLAlchemy com os campos exatos do SPEC.md:

Competition: id (UUID str), name, status (draft|active|finished),
duration_s (int), meters_lap (int, 25 ou 50),
started_at (Float nullable), finished_at (Float nullable), created_at (Float)

Team: id (UUID str), competition_id (FK), name

Lane: id (UUID str), competition_id (FK), number (int 1-8),
team_id (FK nullable), laps (int default 0), status (waiting|active|finished)

LapEvent: id (UUID str), lane_id (FK), lap_number (int),
recorded_at (Float — timestamp do servidor), is_undo (bool default False)

Índices: LapEvent.lane_id, LapEvent.recorded_at

### backend/app/schemas.py
Pydantic schemas (separar Request e Response):
- CompetitionCreate, CompetitionResponse
- TeamCreate, TeamResponse
- LaneResponse, LaneAssign (body para atribuir equipe)
- LapEventResponse
- WSMessage (type: str, payload: dict)

### backend/app/ws_manager.py
Classe ConnectionManager:
- active_connections: list[WebSocket]
- async connect(websocket)
- disconnect(websocket)
- async broadcast(message: dict) — envia para todos os conectados
- async send_to(websocket, message: dict)

### backend/app/timer.py
Classe CompetitionTimer:
- Gerencia o cronômetro com asyncio.create_task
- start(competition_id, duration_s, manager: ConnectionManager)
- pause()
- reset()
- get_state() → dict com elapsed_s e remaining_s
- Envia mensagem type="tick" via manager a cada segundo quando ativo

### backend/app/main.py
FastAPI app com:
- Lifespan: init_db na startup
- StaticFiles montado em "/" servindo ../frontend
- Roteador /api com todos os endpoints do SPEC.md
- Endpoint WebSocket em /ws
- CORS liberado para qualquer origin (rede local)
- GET /api/health retorna {"status": "ok", "version": "1.0.0"}

Endpoints REST conforme SPEC.md:
GET  /api/competition/current
POST /api/competition
POST /api/competition/{id}/start
POST /api/competition/{id}/reset (requer senha no body)
POST /api/team
POST /api/lane/{id}/assign
POST /api/lane/{id}/lap     ← timestamp vem do servidor (time.time())
DELETE /api/lane/{id}/lap/last ← só permite se último lap foi há < 30s

WebSocket /ws:
- Na conexão: envia state completo
- Recebe mensagens do cliente e executa ação correspondente
- Após qualquer mutação: broadcast do state atualizado para todos

### backend/Dockerfile
FROM python:3.11-slim

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]

### start.sh
Script bash que:
1. Cria pasta data/ se não existir
2. Faz cópia do banco se existir: cp data/swimtimer.db data/backup_$(date +%Y%m%d_%H%M).db
3. Roda docker compose up --build -d
4. Aguarda health check (curl em loop até retornar 200)
5. Exibe as URLs (localhost e 10.42.0.1)
Torna-se executável com chmod +x

### frontend/index.html
Página de entrada simples com três botões:
- 📱 Fiscal → fiscal.html
- 📺 Dashboard → dashboard.html
- ⚙️ Admin → admin.html
Mesmo visual do sistema atual (fundo escuro, azul ciano)

### frontend/static/app.js
Classe WSClient:
- constructor(url, onMessage)
- connect() com reconexão exponential backoff (1s → 2s → 4s → 8s → 30s máx)
- send(message: object)
- Evento onStatusChange(connected: bool) para atualizar badge visual

### frontend/fiscal.html + static/fiscal.js
Mobile-first. Exatamente o que o sistema atual tem, mas:
- Conecta via WebSocket em vez de polling
- Botão REGISTRAR envia {type: "lap", lane_id: "uuid"} pelo WS
- Botão DESFAZER envia {type: "undo", lane_id: "uuid"} pelo WS
- Recebe confirmações pelo WS e atualiza UI
- Badge verde/vermelho de status de conexão
- Ao receber state: atualiza contadores de chegadas de cada equipe

### frontend/dashboard.html
Igual ao sistema atual mas recebe dados via WS:
- Ao receber type="state": reconstrói ranking
- Ao receber type="tick": atualiza cronômetro
- Ao receber type="lap": animação suave na linha da equipe

### frontend/admin.html
Interface de configuração:
- Formulário criar competição (nome, duração em horas, metros por comprimento)
- Lista de equipes com botão para adicionar
- Grid de raias (1-8) com dropdown para atribuir equipe
- Botão INICIAR PROVA (envia {type: "timer_start"} pelo WS)
- Botão PAUSAR
- Botão ZERAR (abre modal de senha, envia {type: "timer_reset", password: "xxx"})

### backend/tests/test_api.py
Testes com pytest + httpx AsyncClient:
- test_health: GET /api/health retorna 200
- test_create_competition: POST cria e retorna competition
- test_register_lap: POST /api/lane/{id}/lap registra com timestamp do servidor
- test_undo_lap_within_30s: DELETE retorna sucesso
- test_undo_lap_after_30s: DELETE retorna 400

Importante: usar banco SQLite em memória nos testes (:memory:)

## Após o OpenCode gerar o scaffold

Execute na ordem:

```bash
# 1. Verificar estrutura gerada
find swimtimer/ -type f | sort

# 2. Subir o servidor
cd swimtimer
./start.sh

# 3. Testar health
curl http://localhost:8080/api/health

# 4. Rodar testes
cd backend
pip install -r requirements.txt
pytest tests/ -v

# 5. Abrir no browser
xdg-open http://localhost:8080
```

Se tudo passar, M1.1 está concluído. Avise e sigo com o prompt do M1.2.
